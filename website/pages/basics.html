Values and variables

The building blocks: how to store values, which kinds of values exist and how to combine them.

Comments

Two dashes start a comment that runs to the end of the line. Three dashes on their own line start and end a block comment.

-- this is a comment
yap("hi")  -- so is this

---
This is a block comment.
It can span as many lines as you like.
---
Heads up

Because -- starts a comment, Sigma has no x-- operator. Write x -= 1 instead. (x++ works.)

Variables

Write a name, a colon and a value. The first assignment creates the variable; later ones change it.

name: "Ada"
age: 36
age: age + 1
yap(name, age)

Ada 37

Names can contain letters, digits and underscores, and can't start with a digit. The convention is snake_case.

You don't declare types. A variable can hold any kind of value, and the compiler works out the types on its own to make your code fast.

Updating a variable

score: 10
score += 5     -- 15
score -= 3     -- 12
score *= 2     -- 24
score /= 4     -- 6
score %= 4     -- 2
score++        -- 3
yap(score)

3

These need an existing variable, so a typo like scroe += 1 is caught as an error instead of quietly creating a new variable.

Constants

Use lock for values that should never change. Trying to change one is a compile error.

lock MAX_PLAYERS: 4
MAX_PLAYERS: 5

error: 'MAX_PLAYERS' is locked, so it can't be changed

Numbers

There's one number type: a 64-bit floating point number, the same as JavaScript's numbers or Python's floats. Whole numbers up to 9,007,199,254,740,992 are exact and print without a decimal point.

yap(7 / 2, 2 ** 10, 0.1 + 0.2, 1_000_000, 0xFF)

3.5 1024 0.30000000000000004 1000000 255

Booleans

true and false. If you prefer, nocap means true and cap means false.

online: nocap
yap(online, not online)

true false

nil

nil means "no value". You get it from a missing map field, a function that doesn't serve anything, or num() on text that isn't a number.

user: {name: "Ada"}
yap(user.email)
yap(num("abc") == nil)

Dividing by zero, or taking a remainder by zero, is an error rather than silently producing infinity.

and and or always give back true or false, and they stop early: in a or b, b isn't evaluated when a is truthy.

Because they give back booleans, name or "guest" is true, not the name. To pick between two values, use fr:

name: nil
shown: "guest"
fr name != nil { shown: name }
yap(shown)

guest

Order of operations

From tightest to loosest:

  1. Calls, indexing and fields: f(x), list[0], user.name
  2. ** (groups right to left, so 2 ** 3 ** 2 is 2 ** 9)
  3. Unary minus: -x (so -2 ** 2 is -4)
  4. * / %
  5. + -
  6. .. and ..=
  7. == != < > <= >=
  8. not
  9. and
  10. or

Comparisons can't be chained. Write 0 < x and x < 10 rather than 0 < x < 10; the compiler tells you if you forget.

Truthiness

Conditions don't have to be booleans. These values count as false; everything else counts as true:

  • false and nil
  • 0
  • the empty string "", the empty list [] and the empty map {}
todo: []
fr not todo { yap("nothing to do") }

nothing to do

Lines and statements

Each statement goes on its own line. To put several on one line, separate them with ;.

x: 1; y: 2; yap(x + y)

Inside ( ), [ ] and map braces you can break lines anywhere, which is handy for long lists and calls:

colors: [
    "red",
    "green",
    "blue",
]

Outside brackets, keep a binary operator on the same line as the value before it. Method chains can continue on the next line with a leading dot:

names: ["Kai", "zara", "Milo"]
total_length: len(names[0]) +
    len(names[1])
shout: names
    .map(n => n.upper())
    .join(", ")

A line that computes something but doesn't use it, like x + 1 on its own, is an error, because it's almost always a mistake. Only function calls can stand alone.
