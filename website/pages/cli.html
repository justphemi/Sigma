The sig command

sig compiles, runs, checks and builds Sigma programs.

Commands

CommandDoes
sig file.sgm [args...]Compile (using the cache) and run. Arguments after the file go to args().
sig run file.sgm [args...]Same as above
sig build file.sgm [-o name]Make a standalone executable. The default name is the file name without .sgm.
sig check file.sgmReport compile errors without running. Exit status 0 if the file is fine.
sig emit file.sgmPrint the generated C code
sig cleanDelete the compile cache
sig versionPrint the version (also --version, -v)
sig helpPrint a summary of these commands (also --help, -h)

Environment variables

VariableEffect
SIGMA_CCThe C compiler to use, like clang or gcc-14
CCUsed if SIGMA_CC isn't set. Otherwise Sigma uses cc.
SIGMA_CACHEWhere compiled programs are cached
XDG_CACHE_HOMEIf set (and SIGMA_CACHE isn't), the cache is $XDG_CACHE_HOME/sigma

The default cache is ~/.cache/sigma. It's safe to delete at any time.

Exit status

  • Your program's own status when it runs (0, or whatever it passes to exit).
  • 1 for a compile error or an uncaught runtime error.

Running a file as a script

Start a file with a #! line and mark it executable, and you can run it like any other command. Sigma ignores a first line that starts with #!.

#!/usr/bin/env sig
yap("hi from a script")

hi from a script

chmod +x hello
./hello

This uses the cache like sig hello would, so it starts instantly after the first run. For a tool other people will install, sig build is still the better choice, since it doesn't need Sigma on their machine.
