Control flow

Making decisions with fr and nah, and repeating work with grind.

fr, nah fr, nah

fr runs a block when a condition is truthy. Add as many nah fr branches as you need and an optional final nah.

score: 82

fr score >= 90 {
    yap("A")
} nah fr score >= 80 {
    yap("B")
} nah fr score >= 70 {
    yap("C")
} nah {
    yap("keep grinding")
}

B

No parentheses are needed around the condition. The braces are required, but short blocks can sit on one line:

age: 20
fr age >= 18 { yap("welcome") } nah { yap("come back later") }

nah can start on the line after the closing brace, if you prefer that style:

ready: true
fr ready {
    yap("go")
}
nah {
    yap("wait")
}

grind: one keyword for every loop

Counting with a range

grind i in 0..3 { yap(i) }      -- 0, 1, 2 (stops before 3)
grind i in 1..=3 { yap(i) }     -- 1, 2, 3 (includes 3)

2
1
2
3

Ranges count up by one. If the end is smaller than the start, the loop doesn't run. To count down, loop over a range and subtract:

grind i in 0..3 { yap(3 - i) }

1

Looping over a list

squad: ["Ana", "Ben", "Cy"]
grind name in squad { yap("hey {name}") }
grind i, name in squad { yap("{i}: {name}") }

hey Ana
hey Ben
hey Cy
0: Ana
1: Ben
2: Cy

With two names, the first is the position (starting at 0) and the second is the item.

Looping over a map or a string

prices: {rice: 2500, beans: 1800}
grind item, price in prices { yap("{item} costs {price}") }
grind item in prices { yap(item) }
grind ch in "ok" { yap(ch) }

rice costs 2500
beans costs 1800
rice
beans
o
k

Maps loop in the order their keys were added. With one name you get the keys; with two you get each key and its value.

While a condition holds

lives: 3
grind lives > 0 {
    yap("lives left: {lives}")
    lives -= 1
}

lives left: 3
lives left: 2
lives left: 1

Forever

grind with nothing after it loops until you dip out:

n: 1
grind {
    n *= 2
    fr n > 100 { dip }
}
yap(n)

128

dip and skip

dip leaves the loop immediately (break). skip jumps to the next round (continue). Both apply to the innermost loop.

grind i in 1..=10 {
    fr i % 2 == 0 { skip }
    fr i > 7 { dip }
    yap(i)
}

1
3
5
7

Using dip or skip outside a loop is a compile error.

Changing a list while you loop over it

A grind ... in list loop reads the list as it goes, so items you push during the loop get visited too, and a loop that keeps pushing never ends. To build a new list from an old one, push into a separate list (or use filter and map):

nums: [1, 2, 3, 4, 5, 6]
evens: []
grind n in nums {
    fr n % 2 == 0 { evens.push(n) }
}
yap(evens, nums.filter(n => n % 2 == 1))

[2, 4, 6] [1, 3, 5]

Variables in blocks

Blocks don't create a new scope. A variable first assigned inside an fr or a loop still exists after it, which makes "find something" loops simple:

found: nil
grind name in ["Ana", "Ben", "Bisi"] {
    fr name.starts("B") {
        found: name
        dip
    }
}
yap(found)

Ben

The loop variable itself (like name above) belongs to the loop.
