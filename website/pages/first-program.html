Your first program

This page walks through writing a program, running it, fixing a mistake and turning it into an app you can share.

Hello, world

Make a new folder, and inside it create a file called hello.sgm. Sigma files end in .sgm.

yap("Hello, world!")

Hello, world!

Run it from the terminal:

sig hello.sgm

yap prints whatever you give it. There's no main function to write: Sigma runs the file from top to bottom.

Variables and input

Give a value a name with a colon. Read a line from the user with ask. Put any expression inside { } in a string to drop its value in.

name: ask("What's your name? ")
born: num(ask("What year were you born? "))
age: 2026 - born
yap("Nice to meet you, {name}. You turn {age} this year.")

What's your name? What year were you born? Nice to meet you, Ada. You turn 211 this year.

(The output looks squashed here because the input came from a file instead of a keyboard. In a real terminal, each answer appears after its question.)

ask always gives back text, so num(...) turns it into a number. If the text isn't a number, num returns nil, which you can check for.

Making decisions

temperature: 31

fr temperature > 30 {
    yap("it's hot, stay inside")
} nah fr temperature > 15 {
    yap("nice weather")
} nah {
    yap("grab a jacket")
}

it's hot, stay inside

fr means "if", nah fr is "else if" and nah is "else".

Repeating things

Every loop in Sigma starts with grind:

grind i in 1..=3 {
    yap("round {i}")
}

foods: ["jollof", "suya", "puff-puff"]
grind food in foods {
    yap("I like {food}")
}

round 1
round 2
round 3
I like jollof
I like suya
I like puff-puff

Your own functions

Define functions with cook and give back a result with serve:

cook area(width, height) {
    serve width * height
}

yap(area(3, 4))

When something is wrong

Sigma checks your whole program before running it. Here's a typo:

total: 0
grind i in 0..3 { totl += i }

error: 'totl' is not defined
 --> main.sgm:2:19
  |
2 | grind i in 0..3 { totl += i }
  |                   ^^^^
  = hint: did you mean 'total'?

The message tells you the file, the line and the column, points at the problem and suggests a fix. Errors that can only happen while the program runs, like reading past the end of a list, print the line they happened on:

scores: [90, 85]
yap(scores[2])

error: index 2 is out of range (the list has 2 items)
  --> main.sgm:2

You can catch these with yolo and oops. See Errors.

To check a program for mistakes without running it, use sig check:

sig check hello.sgm

Build an app you can share

sig build makes a standalone executable. It doesn't need Sigma or a C compiler to run, so you can send it to anyone on the same kind of computer (for example, another Mac with the same type of chip).

sig build hello.sgm -o hello
./hello

built hello
Hello, world!
