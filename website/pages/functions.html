Functions

Named functions with cook, quick inline functions with =>, and how variables are shared between them.

Defining a function

cook add(a, b) {
    serve a + b
}

yap(add(2, 3))

5
  • cook defines a function. Functions are defined at the top level of a file, not inside other blocks.
  • serve gives back a value and leaves the function. A function that ends without serve, or with a bare serve, gives back nil.
  • Call it by name with parentheses. The number of arguments must match, and the compiler checks this.

Functions can be called before they're defined in the file, so you can put the main logic at the top and helpers at the bottom.

yap(shout("hello"))

cook shout(text) {
    serve text.upper() + "!"
}

HELLO!

Returning early

cook grade(score) {
    fr score >= 90 { serve "A" }
    fr score >= 80 { serve "B" }
    serve "C"
}
yap(grade(95), grade(85), grade(10))

A B C

Returning several values

Serve a list or a map:

cook stats(nums) {
    serve {low: min(nums), high: max(nums), avg: nums.sum() / len(nums)}
}
s: stats([4, 8, 15, 16, 23, 42])
yap(s.low, s.high, s.avg)

4 42 18

Recursion

cook fib(n) {
    fr n < 2 { serve n }
    serve fib(n - 1) + fib(n - 2)
}
yap(fib(20))

6765

If a recursive function never stops, the program ends with a clear "stack overflow" message instead of hanging.

Lambdas

A lambda is a function without a name, written with =>. They're values, so you can store them in variables, put them in lists and maps, and pass them to other functions.

double: x => x * 2
add: (a, b) => a + b
hello: () => "hello"
yap(double(21), add(1, 2), hello())

42 3 hello

For more than one expression, give the lambda a block and serve the result:

describe: (n) => {
    fr n > 0 { serve "positive" }
    fr n < 0 { serve "negative" }
    serve "zero"
}
yap(describe(-4))

negative

Lambdas are what you pass to list methods like map, filter and sort:

nums: [5, 3, 8, 1]
yap(nums.map(n => n * 10), nums.filter(n => n > 2), nums.sort(n => -n))

[50, 30, 80, 10] [5, 3, 8] [8, 5, 3, 1]

Named functions as values

Use a cook function's name without parentheses to pass it around:

cook square(x) { serve x * x }
yap([1, 2, 3].map(square))

[1, 4, 9]

Closures

A lambda can use variables from where it was created. It takes a copy of their values at that moment:

cook multiplier(k) {
    serve x => x * k
}
triple: multiplier(3)
times10: multiplier(10)
yap(triple(7), times10(7))

21 70

Because it's a copy, a lambda can't reassign an outer variable. To keep changing state inside a lambda, store it in a map or list, which are shared rather than copied:

counter: {n: 0}
tick: () => { counter.n += 1 }
tick()
tick()
yap(counter.n)

2

Scope: where variables live

  • Top-level variables (assigned outside any function) are global. Every cook function can read and change them.
  • Variables first assigned inside a function are local to that call.
  • Parameters are always local, even if a global has the same name.
high_score: 0

cook submit(score) {
    fr score > high_score { high_score: score }
    bonus: score / 10     -- local to submit
    serve bonus
}

submit(40)
submit(95)
submit(60)
yap(high_score)

95
Tip

Because functions can change globals, give globals clear names and keep most state local. Passing values in and serving results out keeps functions easy to test.
