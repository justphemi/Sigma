Maps

Maps store values under string keys. Use them for records (a user, a product), lookup tables, counters, and objects with methods.

Creating and reading

user: {name: "Peters", age: 24, "favourite food": "amala"}

yap(user.name)
yap(user["age"])
yap(user["favourite food"])
yap(user.email)

Peters
24
amala
nil

Keys that are plain names can be written bare; other keys need quotes. Read a field with a dot, or with square brackets when the key has spaces or is stored in a variable. A missing key gives nil.

Adding and changing

user: {name: "Peters", score: 10}
user.score: 50
user.score += 5
user.level: 2
key: "city"
user[key]: "Abuja"
yap(user)

{name: "Peters", score: 55, level: 2, city: "Abuja"}

Maps remember the order keys were added in, and print and loop in that order.

Checking and removing

stock: {rice: 4, beans: 0}
yap(stock.has("rice"), stock.has("yam"))
yap(stock.get("yam", 0))
stock.del("beans")
yap(stock, len(stock))

true false
0
{rice: 4} 1

has checks whether a key exists (a key can exist with the value nil or 0). get(key, default) reads a key and falls back to default when it's missing.

Keys, values and loops

ages: {Ada: 36, Tolu: 28}
yap(ages.keys(), ages.values())
grind name, age in ages { yap("{name} is {age}") }

["Ada", "Tolu"] [36, 28]
Ada is 36
Tolu is 28

Counting things

A very common pattern: count how often each value appears.

votes: ["jollof", "suya", "jollof", "puff-puff", "jollof", "suya"]
counts: {}
grind v in votes {
    counts[v]: counts.get(v, 0) + 1
}
grind food in counts.keys().sort(k => counts[k], "desc") {
    yap(food, counts[food])
}

jollof 3
suya 2
puff-puff 1

Number keys

Keys are always strings. A number used as a key is converted to text, so m[1] and m["1"] are the same entry.

Maps as objects

Store lambdas in a map to give it methods. Calling thing.method() calls the function stored under that key.

cook make_account(owner) {
    acct: {owner: owner, balance: 0}
    acct.deposit: (amount) => { acct.balance += amount }
    acct.report: () => "{acct.owner} has {acct.balance}"
    serve acct
}

a: make_account("Chi")
a.deposit(500)
a.deposit(250)
yap(a.report())

Chi has 750

This works because the lambdas hold a reference to the same map, so changes to acct.balance are shared.

Avoid naming a method after one of the built-in map methods (keys, values, has, get, del, copy, clear): calling m.keys() always runs the built-in one. Any other name works.

Shared, not copied

Like lists, maps are shared when assigned or passed to a function. Use copy() for an independent map (it copies the top level only).
