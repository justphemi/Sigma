Modules

Split a program across files with yoink.

yoink

Put shared functions in their own file:

-- mathx.sgm
lock TAU: 6.283185307179586

cook clamp(x, low, high) {
    fr x < low { serve low }
    fr x > high { serve high }
    serve x
}

cook mean(nums) {
    serve nums.sum() / len(nums)
}

Then yoink it from another file and use its functions, constants and variables directly:

yoink "mathx.sgm"

yap(clamp(150, 0, 100))
yap(mean([2, 4, 9]))
yap(round(TAU))

100
5
6

How it works

  • Paths are relative to the file that contains the yoink, not to the folder you run sig from. Subfolders work: yoink "lib/strings.sgm".
  • Each file is included once, even if several files yoink it, so shared helpers are safe to yoink from anywhere.
  • The top-level code in a yoinked file runs once, before the code after the yoink.
  • Everything lives in one namespace. Two files can't both define a function with the same name; the compiler reports both places so you can rename one.
  • yoink goes at the top level of a file, usually at the start.

Missing files are reported when you compile:

yoink "helpers.sgm"

error: can't yoink './helpers.sgm': No such file or directory
 --> main.sgm:1:1
  |
1 | yoink "helpers.sgm"
  | ^
  = hint: paths are relative to the file doing the yoink

Naming

Because all files share one namespace, it helps to give functions in a library file a short common prefix, like str_pad and str_center, or to group them in a map:

-- textx.sgm
textx: {
    pad: (s, n) => s + " ".repeat(n - len(s)),
    center: (s, n) => " ".repeat(floor((n - len(s)) / 2)) + s,
}

Callers then write textx.pad("hi", 10). See project layout for how to organise a bigger program.
