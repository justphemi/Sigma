Project layout

A simple, conventional structure for a Sigma project that grows beyond one file.

A typical project

my-app/
  main.sgm            entry point: reads arguments, calls into lib/
  lib/
    parse.sgm         one file per area of the program
    report.sgm
  tests/
    test_parse.sgm    tests use vibecheck
    test_report.sgm
    run.sh            runs every test
  data/               sample input files
  build/              executables from sig build (not committed)
  Makefile            optional shortcuts
  README.md
  .gitignore
  • One entry point. main.sgm handles arguments and input, and calls functions from lib/. Keep it short.
  • Library files define functions and maybe a few lock constants, but don't do work at the top level. That way any file can yoink them without side effects, including tests.
  • Paths in yoink are relative to the file, so main.sgm writes yoink "lib/parse.sgm" and a test in tests/ writes yoink "../lib/parse.sgm".

The entry point

-- lib/report.sgm
cook summarize(nums) {
    fr len(nums) == 0 { serve "no data" }
    serve "count {len(nums)}, min {min(nums)}, max {max(nums)}, avg {round(nums.sum() / len(nums))}"
}

-- main.sgm
yoink "lib/report.sgm"

cook main(argv) {
    fr len(argv) != 1 {
        yap("usage: my-app ")
        serve 2
    }
    nums: []
    grind line in read_file(argv[0]).split() {
        n: num(line)
        fr n != nil { nums.push(n) }
    }
    yap(summarize(nums))
    serve 0
}

write_file("data.txt", "4\n8\n15\n16\n23\n42\n")  -- sample input for this example
exit(main(args()))

count 6, min 4, max 42, avg 18

Wrapping the program in a main function keeps its variables local and gives you one place to decide the exit status.

.gitignore

build/
*.txt.bak
.DS_Store

Executables made with sig build are specific to one operating system and processor, so don't commit them. Build them in CI instead (see Shipping).

A Makefile for shortcuts

Optional, but it saves typing:

run:
	sig main.sgm data/sample.txt

check:
	sig check main.sgm

test:
	sh tests/run.sh

build:
	mkdir -p build
	sig build main.sgm -o build/my-app

.PHONY: run check test build

(Makefile lines must start with a tab, not spaces.)

Style

  • snake_case for variables and functions, UPPER_CASE for lock constants.
  • Four spaces of indentation.
  • Small functions that take values in and serve results out are the easiest to test.
  • Use maps for records, and keep the same keys in every record of a kind.
  • Put a short comment at the top of each file saying what's in it.
