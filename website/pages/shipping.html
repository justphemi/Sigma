Shipping

Turn a Sigma program into a single executable file that runs without Sigma installed.

sig build

sig build main.sgm -o my-app
./my-app

Without -o, the executable is named after the file (main.sgm becomes main). It contains your code, every yoinked file and the Sigma runtime, compiled with optimizations. It doesn't read the .sgm files at run time, so you only ship the one file.

Where it runs

An executable runs on the same kind of system it was built on:

  • Built on a Mac with Apple silicon: runs on Macs with Apple silicon.
  • Built on an Intel Mac: runs on Intel Macs (and on Apple silicon through Rosetta).
  • Built on Linux: runs on Linux with the same processor type and a similar or newer system library (glibc). Building on an older distribution, such as the oldest Ubuntu you support, gives the widest reach.

To support several systems, build on each one. CI makes that easy (below).

Installing for yourself

sig build main.sgm -o my-app
sudo mv my-app /usr/local/bin/

Or into a folder you own, like ~/.local/bin, if it's on your PATH.

Releasing on GitHub

This workflow builds executables for Linux and macOS whenever you push a version tag like v1.0.0, and attaches them to a GitHub release. Save it as .github/workflows/release.yml:

name: release
on:
  push:
    tags: ["v*"]

permissions:
  contents: write

jobs:
  build:
    strategy:
      matrix:
        include:
          - os: ubuntu-22.04
            name: linux-x64
          - os: macos-14
            name: macos-arm64
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - name: Install Sigma
        run: |
          git clone --depth 1 https://github.com/justphemi/Sigma.git /tmp/sigma
          cd /tmp/sigma && ./build.sh
      - name: Build
        run: /tmp/sigma/build/sig build main.sgm -o my-app-${{ matrix.name }}
      - uses: softprops/action-gh-release@v2
        with:
          files: my-app-${{ matrix.name }}

git tag v1.0.0
git push origin v1.0.0

Looking at the generated C

sig emit prints the C code Sigma generates. It's useful for curiosity, for checking what the compiler did with a hot loop, or for building on a system where you have a C compiler but not Sigma:

sig emit main.sgm > main.c
cc -O2 main.c -o my-app -lm

The C file is self-contained: the runtime is included in it.

Before you ship

  • Run sig check and your tests.
  • Make error cases exit with a non-zero status (exit(1)), so scripts that call your tool can tell when it failed.
  • Print usage help when the arguments are wrong.
  • Remember there's no garbage collector yet: a tool that processes input and exits is perfect; a program meant to run for days is not (see limitations).
