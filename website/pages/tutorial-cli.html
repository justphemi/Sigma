Tutorial: a to-do app

Build a real command-line tool from scratch: a to-do list that saves to a file, handles bad input, and ships as a single executable.

Here's the finished app in use:

todo add buy plantain
todo add finish the docs
todo done 2
todo list

added: buy plantain
added: finish the docs
nice, finished: finish the docs
1. [ ] buy plantain
2. [x] finish the docs

Along the way you'll use modules, maps, files and arguments, and error handling.

1. Plan the data

Each task has some text and a done flag. In the program, a task is a map:

task: {done: false, text: "buy plantain"}

On disk, we'll save one task per line, starting with x for done tasks and a space for open ones, then a | and the text:

 |buy plantain
x|finish the docs

A plain-text format like this is easy to read, easy to edit by hand and easy to parse.

2. Set up the project

mkdir todo
cd todo
mkdir lib

We'll keep the code that reads and writes the file in lib/store.sgm, and the command handling in todo.sgm:

todo/
  todo.sgm         the app: reads the command and runs it
  lib/
    store.sgm      loading and saving tasks

3. Loading and saving

Create lib/store.sgm:

-- lib/store.sgm: load and save tasks as lines of text
-- Each line is "x|text" for a done task, or " |text" for an open one.

cook load_tasks(path) {
    tasks: []
    fr not file_exists(path) { serve tasks }
    grind line in read_file(path).split("\n") {
        fr len(line) < 2 { skip }
        tasks.push({done: line[0] == "x", text: line.slice(2)})
    }
    serve tasks
}

cook save_tasks(path, tasks) {
    out: ""
    grind t in tasks {
        mark: " "
        fr t.done { mark: "x" }
        out += "{mark}|{t.text}\n"
    }
    write_file(path, out)
}

A few things to notice:

  • If the file doesn't exist yet (the first run), load_tasks serves an empty list instead of failing.
  • skip ignores blank lines, like the empty piece after the last new line.
  • line[0] is the first character, and line.slice(2) is everything after x|.
  • save_tasks builds the whole file in one string with +=, which is fast in Sigma, then writes it in one go.

4. The app

Create todo.sgm:

yoink "lib/store.sgm"

lock FILE: "todo.txt"

cook show(tasks) {
    fr len(tasks) == 0 {
        yap("nothing to do")
        serve
    }
    grind i, t in tasks {
        mark: " "
        fr t.done { mark: "x" }
        yap("{i + 1}. [{mark}] {t.text}")
    }
}

cook task_number(text, tasks) {
    n: int(text)
    fr n == nil or n < 1 or n > len(tasks) {
        yeet "there's no task {text} (you have {len(tasks)})"
    }
    serve n - 1
}

cook usage() {
    yap("usage:")
    yap("  todo list")
    yap("  todo add ")
    yap("  todo done ")
    yap("  todo remove ")
}

a: args()
fr len(a) == 0 {
    usage()
    exit(1)
}

tasks: load_tasks(FILE)
command: a[0]
rest: a.slice(1).join(" ")

yolo {
    fr command == "list" {
        show(tasks)
    } nah fr command == "add" {
        vibecheck(rest != "", "add needs some text")
        tasks.push({done: false, text: rest})
        save_tasks(FILE, tasks)
        yap("added: {rest}")
    } nah fr command == "done" {
        i: task_number(rest, tasks)
        tasks[i].done: true
        save_tasks(FILE, tasks)
        yap("nice, finished: {tasks[i].text}")
    } nah fr command == "remove" {
        i: task_number(rest, tasks)
        gone: tasks.del(i)
        save_tasks(FILE, tasks)
        yap("removed: {gone.text}")
    } nah {
        yap("unknown command '{command}'")
        usage()
        exit(1)
    }
} oops e {
    yap("error: {e}")
    exit(1)
}

How it fits together:

  • yoink "lib/store.sgm" brings in load_tasks and save_tasks.
  • args() holds the words after the program name. The first is the command; the rest are joined back into the task text, so todo add buy plantain works without quotes.
  • task_number turns what the user typed into a list position and yeets a friendly error if it isn't a valid task number.
  • The whole command runs inside one yolo. Any problem, whether it's ours (yeet, vibecheck) or Sigma's (a file that can't be written), ends up in oops, which prints it and exits with status 1.
  • tasks[i].done: true changes the map inside the list directly, because maps are shared, not copied.

5. Try it

sig todo.sgm add buy plantain
sig todo.sgm add finish the docs
sig todo.sgm add call mum
sig todo.sgm done 2
sig todo.sgm remove 1
sig todo.sgm list

added: buy plantain
added: finish the docs
added: call mum
nice, finished: finish the docs
removed: buy plantain
1. [x] finish the docs
2. [ ] call mum

And the mistakes a user might make:

sig todo.sgm done 9
sig todo.sgm add

error: there's no task 9 (you have 2)
error: vibe check failed: add needs some text

Look at todo.txt to see the saved data:

x|finish the docs
 |call mum

The first run of each version takes about a second while Sigma compiles. Every run after that starts instantly from the cache.

6. Ship it

Turn it into a standalone executable and put it on your PATH:

sig build todo.sgm -o todo
sudo mv todo /usr/local/bin/
todo list

The executable has everything built in, including lib/store.sgm, so it works from any folder without Sigma installed. It saves todo.txt in whatever folder you run it from. See Shipping for more.

7. Ideas to extend it

  • Add todo clear to remove every finished task. (Hint: tasks.filter(t => not t.done).)
  • Add priorities: todo add !buy plantain, and sort high-priority tasks first with sort.
  • Show a summary like 3 open, 2 done at the end of list.
  • Write tests for load_tasks and save_tasks using the approach in Testing.
